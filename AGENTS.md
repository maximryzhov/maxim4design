# AGENTS.md — Правила для AI-агентов и регламент задач

Данный файл содержит обязательные правила, регламент ведения задач и формат карточек для автономных AI-агентов и разработчиков, работающих над проектом **maxim4design**.

---

## 1. Регламент работы с задачами

1. **Расположение задач:**
   * Все запланированные и активные задачи хранятся в папке `tasks/` в виде отдельных markdown-файлов: `tasks/TASK-XXX-name.md`.
   * Папка выполненных задач: `/done` (расположена в корне проекта: `done/TASK-XXX-name.md`).

2. **Правило перемещения карточек в `/done`:**
   > [!IMPORTANT]
   > Когда задача полностью реализована, проверена и соответствует всем критериям приемки (Acceptance Criteria / Definition of Done), агент **обязан переместить карточку задачи из папки `tasks/` в папку `done/`** (например, `git mv tasks/TASK-001.md done/` или физическим перемещением файла), обновив статус в метаданных на `status: done` и проставив галочки во всех пунктах чек-листа.

3. **Атомарность и зависимости:**
   * Не начинать задачу, если её зависимости (`dependencies`) ещё не находятся в папке `done/`.
   * Каждая карточка должна закрываться отдельным логическим шагом.

4. **Опора на архитектуру и базу знаний:**
   * При реализации агенты обязаны руководствоваться [ARCHITECTURE.md](file:///e:/Projects/Dev/html2design/ARCHITECTURE.md) (спецификация типов FIR и архитектура) и [KNOWLEDGE_BASE.md](file:///e:/Projects/Dev/html2design/KNOWLEDGE_BASE.md) (решения известных багов со шрифтами, SVG, текстом и т.д.).

---

## 2. Стандартный формат карточки задачи

Каждая карточка в `tasks/` и `done/` должна строго следовать следующему формату:

```markdown
---
id: TASK-XXX
title: Краткое название задачи
status: pending # pending | in_progress | done | blocked
priority: high # low | medium | high | critical
phase: 1 # Номер фазы из ARCHITECTURE.md
dependencies: [] # Список ID задач, например [TASK-001]
tags: [extractor, figma-plugin, types, styles]
---

# TASK-XXX: Название задачи

## 1. Описание задачи
Подробное описание того, что требуется сделать, какую часть системы реализует или какую проблему решает.
```

## 3. Правила написания кода для проекта

1. **Строгая типизация TypeScript:** Никаких неявных `any`. Все типы нод должны наследоваться от `FIRNode` из контракта данных.
2. **Безопасность песочницы Figma:** Любые операции с `figma.loadFontAsync` или `figma.createNodeFromSvg` обязательно оборачиваются в `try/catch` с fallback-логикой, описанной в KNOWLEDGE_BASE.md.
3. **Изоляция окружений:** Код экстрактора не должен зависеть от API Figma, а код генератора плагина не должен обращаться к `window` или `document` браузера.
