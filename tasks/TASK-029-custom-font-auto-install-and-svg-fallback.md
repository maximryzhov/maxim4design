# TASK-029: Извлечение кастомных @font-face шрифтов, локальная установка/мост и фикс переноса длинных слов

## 1. Описание задачи
На реальных сайтах (например, `alfagreen-fitosteny.html`) используются проприетарные/кастомные `@font-face` шрифты (`ContactBebas`, `ProcessMontserrat`, `ContactBebasExpanded`). Поскольку Figma Plugin API не умеет загружать бинарные шрифты в рантайме, при их отсутствии в ОС происходит откат на `Inter`, что даёт визуальные расхождения и разрывы длинных слов (например, `ИСКУССТВЕННЫ\nЕ` в баннере `НАСТОЯЩИЕ ВПЕЧАТЛЕНИЯ`).

## 3. Технические детали и требования к реализации
- **Автоматическая выгрузка/установка `@font-face` через локальный мост:**
  - В `src/extractor/font-extractor.ts`: гарантировать извлечение `base64`/URL для всех `CSSFontFaceRule` (включая скачивание внешних `.woff2`/`.ttf` через мост/extension).
  - Добавить эндпоинт/обработчик в локальном мосте (или скрипт-установщик), который принимает `fir.fonts`, декодирует `.woff2`/`.ttf` и сохраняет/устанавливает их в пользовательскую папку шрифтов ОС (или отдаёт готовый архив).
- **Умная компенсация при fallback в `src/plugin/text-renderer.ts`:**
  - Для длинных слов в крупных заголовках при fallback с кастомного шрифта на `Inter` увеличивать допустимую ширину (или автоматически рассчитывать `minWidth` по длине самого длинного слова в `characters`), чтобы ни одно слово не рвалось посимвольно (`ИСКУССТВЕННЫ\nЕ`).

## 4. Критерии приемки (Definition of Done)
- [ ] Кастомные `@font-face` шрифты со страницы извлекаются вместе с бинарными данными (`woff2`/`ttf`).
- [ ] Ни одно длинное слово в крупных заголовках (`ИСКУССТВЕННЫЕ`) не переносится с разрывом при fallback на `Inter`.
- [ ] Добавлены unit-тесты для расчёта ширины длинных слов и извлечения бинарных `@font-face`.
